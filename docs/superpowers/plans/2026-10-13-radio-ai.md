# Radio AI Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development. User explicitly requested complete autonomous execution; routine design and implementation decisions are delegated.

**Goal:** Deliver all MVP functionality B01–B25 from the supplied specification.

**Architecture:** Liquidsoap and Icecast run independently of TypeScript. A separate worker persists the catalogue, chooses music, prepares DJ files and records real playback; Next.js supplies an authenticated local administration panel.

**Tech Stack:** Node 24, TypeScript, npm workspaces, Prisma 6/SQLite, Next.js 16/React 19, Zod, Liquidsoap official supported Ubuntu package, Icecast, FFmpeg, OpenAI SDK, Vitest/Playwright.

**Spec:** docs/SPEC_RADIO_AI.md

## Global Constraints

- Continuous audio must survive failure of DB, worker, UI, network or AI providers.
- No Docker; native Ubuntu services, loopback control ports, secrets outside Git.
- AI break played state comes from actual audio events, never enqueue acknowledgement.
- Structured scripts, bounded external timeouts, validated audio, hourly UTC identity with editorial Europe/Madrid timezone.
- UI follows light Geist operational design; no secrets in responses.

## Review Focus

- Small libraries relax artist then track windows without selecting missing audio.
- DST repeated hour has distinct UTC keys; skipped hour creates no imaginary job.
- Worker crash around push reconciles metadata and prevents duplicate hourly broadcasts.
- Malformed RSS, stale weather, corrupt audio and provider timeouts degrade to music.
- Unauthenticated cross-origin admin requests and traversal paths are rejected.
